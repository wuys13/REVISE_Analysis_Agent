# 06. 假说生命周期与队列扩展

> [返回交付框架总览](README.md) ｜ [生物学故事与证据边界](04_biological_validation_and_stories.md)

本页描述后续科学工作的边界。它不把未来队列、外部验证或湿实验写成当前软件能力，也不规定固定的假说数量或样本列表。

## 1. 假说成熟度

```text
observed
  -> supported association
  -> candidate mechanism
  -> testable proposal
```

| 阶段 | 最低内容 | 不能替代什么 |
| --- | --- | --- |
| `observed` | 当前输入、方法、参数和底表支持的现象 | 机制解释 |
| `supported association` | 多个适用结果、空间上下文、方向和限制 | 因果或外部泛化 |
| `candidate mechanism` | 分子/程序/区域连接、替代解释和可证伪预测 | 实验验证 |
| `testable proposal` | 明确样本、对照、测量和成功/失败判据 | 已完成的湿实验或临床结论 |

状态升级必须新增适用证据；排名靠前、报告生成、载荷存在或脚本退出 0 都不会自动升级状态。假说文档应链接内部结果、历史 case 或外部来源，并逐项写明证据层级。

## 2. 队列扩展的必要登记

当同一问题扩展到多个样本、切片或平台时，至少登记：

| 项目 | 要求 |
| --- | --- |
| 统计实验单位 | patient/donor、sample/section、region/unit 的关系和独立性 |
| 实体对齐 | 亚型或状态定义、映射依据和不确定性；不能按 cluster 编号直接合并 |
| 可评估性 | 输入平台、覆盖、QC、方法前提、缺失、失败和不显著状态 |
| 每样本证据 | 同定义效应量、方向、不确定性、比较口径和结果身份 |
| 聚合 | 先核对可比性，保留异质性；不只汇总 p 值或显著票数 |
| 增量版本 | 固定纳入样本、运行和结果的快照；新结果形成可追溯的新版本 |

工程上复用现有 `batch.py` 的样本 × 分析执行和失败隔离。队列统计、跨样本实体 harmonization、自动摘要和资源调度是独立能力，必须分别标注已实现、计划或未验证；不能由单样本 `summary.json` 推出已具备。

## 3. 外部验证与近期故事

已有论文 case、临床队列、IFA、谱系追踪和湿实验可以为具体命题提供额外支持，但应保留原始来源、支持范围和复核状态。它们不成为所有近期生信故事的统一完成门槛，也不改变当前输入身份或正式结果状态。
