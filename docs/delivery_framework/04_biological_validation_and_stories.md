# 04. 生物学故事与证据边界

> [返回交付框架总览](README.md) ｜ [迁移与验收](../migration.md) ｜ [跨仓库审阅](../cross-repo-review/README.md)

本页规定如何把分析事实组织成可检查的故事。它不预设固定的 H1–H4，也不把论文叙述或外部实验自动写入当前计算结果。

## 1. 一条故事至少包含什么

```text
观察事实
  -> 对应的基因/程序/通讯/区域证据
  -> 空间和单位语境
  -> 解释与候选机制
  -> 支持范围、替代解释、缺口和下一步检验
```

每个关键数字、标签和图应能回到当前 `result.json`、登记底表、输入身份和参数。故事可以引用历史 case 或文献，但要标明它们是历史运行、外部关联还是本次重新计算。

## 2. 证据层级

| 层级 | 可以支持什么 | 不应直接推出什么 |
| --- | --- | --- |
| 输入与技术检查 | 样本身份、标签/表达/坐标是否可用 | 生物学改善或机制成立 |
| 正式计算结果 | 差异、覆盖、程序、空间分布、候选通讯 | 物理接触、功能因果或临床效果 |
| 历史 case / 论文结果 | 对应命题的既有支持和比较背景 | 自动等同于当前输入、标签或参数 |
| 外部临床、IFA、谱系、湿实验 | 关联、定位、来源或功能的额外证据（按原文范围） | 作为当前生信管线的隐式门槛 |
| 科学审阅 | 对证据边界、替代解释和后续问题的判断 | 替代底表、receipt 或技术运行记录 |

CellPhoneDB 或类似表达侧方法给出候选 ligand/receptor 关系；空间邻近、单位身份和功能验证需要分别记录。群级同表达不能直接证明同一个细胞发出并响应，也不能把 score 当作概率或置信度。空间共定位也不自动等于因果、TLS 成熟度、力学或代谢通量。

## 3. 推荐的科学故事卡片

对每个亚型、基因或区域故事，建议保留以下字段：

| 字段 | 内容 |
| --- | --- |
| 对象与问题 | 具体 unit、gene、program、CCI 或区域，以及比较目标 |
| 观察 | 当前实际结果、分母、方向和状态 |
| 证据入口 | `result.json`、表、图、输入身份、参数和历史/外部来源 |
| 空间语境 | 坐标、单位、区域、邻域和覆盖；不把缺失写成零 |
| 解释 | 与现象一致的候选机制，并注明推断层级 |
| 替代解释 | 参考偏差、检测覆盖、聚类 K、窗口、批次或其他混杂 |
| 下一检验 | 能区分候选解释的分析、对照或实验 |
| 状态 | `observed`、`candidate`、`scientific_review_pending`、`limited` 等实际状态 |

这套卡片可以承载 Fig6/7 等既有 case，但必须先登记 case 的输入、cluster 映射、图和底表；不同运行的同名亚型不能按编号直接互换。近期故事围绕已有真实 case 展开时，新队列和新湿实验是额外证明，不应被写成所有故事的统一完成门槛。

## 4. 故事成熟度

```text
observed
  -> supported association
  -> candidate mechanism
  -> testable proposal
```

状态升级需要新增适用证据，不由文档存在、排序靠前、报告生成或脚本退出 0 自动触发。假说可以提出可证伪预测和后续实验，但实验方案不应伪装成已经完成的内部分析。
