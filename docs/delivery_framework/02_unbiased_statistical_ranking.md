# 02. 统计基线与可评估范围

> [返回交付框架总览](README.md) ｜ [分析能力索引](../analyses/README.md)

本页定义阅读和复核统计结果的方式，不声明一个固定的亚群、基因、通路或候选数。每个样本的真实范围来自样本配置、分析参数和 `result.json`；摘要中的 top-N 只是展示选择，不能替代完整底表。

## 1. 先确认范围

阅读任何排序或比较前，先记录：

| 项目 | 必须从哪里确认 |
| --- | --- |
| 样本、平台、输入对象和提交 | `index.json`、`result.json`、输入 manifest 或 source registry |
| Raw/SVC 两侧身份和单位语义 | sample YAML、结果 metadata、方法说明 |
| 标签、基因集、共同轴和空间范围 | 实际结果表的列、参数和比较 metadata |
| 分析是否完整 | `result.status`、阶段状态、`missing_inputs`、错误或不可用原因 |
| 排序范围和截断规则 | 运行参数与底表行数；不能从标题或旧文档推断 |

Raw 和 SVC 可以有不同的单位、ID 和基因集合。只有共同物理定义、共同基因或明确的成员关系成立时，才进行跨侧定量比较；单侧结果仍然保留并说明比较不可用。

## 2. 统计结果的阅读顺序

1. 先看完整结果和分母，再看摘要排名。
2. 区分实际测量、重建输出、派生评分和外部文献标签。
3. 同时记录效应方向、检验方法、背景、缺失值和多重检验处理。
4. 对空间结果记录坐标、单位、邻域/窗口、区域来源和覆盖范围。
5. 对排序结果保留未入选对象的范围说明，避免把展示 top-N 写成全量结论。

`reconstruction_impact` 目前提供 State、Gain、区域、成员和支持诊断；`spatial_autocorrelation` 提供各侧原生空间 Moran；`pathway_activity` 提供显式基因集的覆盖和评分分布。它们的分母和前提不同，不能把一个阶段的排名当成另一个阶段的质量门禁。

## 3. Benchmark 与科学发现的边界

重建方法的多方法 benchmark 属于上游 `REVISE` 的生产责任。本仓库可以消费已登记的比较结果，但不再维护旧的双域目录生成器，也不把历史随机/硬编码表格作为当前事实。

科学发现阅读可以关注全量结果中的 marker、程序、通讯和区域现象；是否形成机制假说要看实际证据链和替代解释。不存在统一的 Moran 提升阈值、最佳方法、固定 K、固定窗口或固定 token 预算可自动裁定所有样本。

## 4. 缺失与限制

没有表达身份、共同基因、空间支持、provider 或足够样本时，输出应保留相应的 `partial`、`unavailable` 或 `skipped` 状态。缺少结果不是零效应，未显著不是未测量，更多检出量也不自动等于灵敏度提高。任何历史数字必须绑定其原始输入、参数、运行时间和证据文件，不能直接移植到新样本。
