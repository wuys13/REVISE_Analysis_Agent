## 2. 同一 Notebook 会话内重跑阶段，存在旧结果混入当前结果的实际问题

这不是风格问题，而是需要优先修正的正确性问题。

### 我发现的情况

`run_stage()` 使用：

```python
before = set(self.outputs)
...
artifacts = sorted(set(self.outputs) - before)
```

识别该阶段产物，但没有在重跑前清理这个阶段及其下游的旧记录。

同时，`_write_region()` 在阈值稳定时写出：

```text
state_<scope>_region_extent.csv
```

当随后重跑变成 `no_stable_threshold` 时，会更新阈值和 mask 表，**却不会从当前输出清单中撤销上一次的 extent 表**。

### 最小复现结果

我将这两个方法的相关逻辑独立重放，用受控阈值返回验证保存行为：

| 同一会话的两次执行 | 结果                 |
| --------- | ------------------ |
| 第一次阈值稳定   | 写出区域数量摘要           |
| 第二次阈值不稳定  | 当前 mask 全部变为未知     |
| 当前输出清单    | **仍然登记第一次的区域数量摘要** |
| 第二次阶段产物记录 | 因路径已经存在，新增产物列表为空   |

也就是说，可能同时出现：

```text
当前 threshold：no_stable_threshold
当前 mask：全部未知
当前 manifest：仍包含上一轮“存在区域”的 extent
```

网页的顶部摘要又会读取 extent，因此存在把旧区域数量当成当前事实的风险。这里复现的是保存与登记逻辑，不是对阈值算法本身的验证。

复现材料：[最小重放脚本](sandbox:/mnt/data/revise_audit/check_rerun.py) · [重放结果](sandbox:/mnt/data/revise_audit/replay_results.json)。

### 为什么与你的使用方式直接相关

你主要想做的就是：

> 看当前结果 → 改参数 → 重跑这一段 → 再判断。

因此，不能只验证“新建一个 workflow，从头执行一次”正确。

**需要验证同一会话里的反复修改也正确。**

### 建议的最小修复

不需要通用依赖图或复杂缓存框架。用现有固定阶段顺序即可：

* 重跑某阶段时，撤销该阶段和受影响后续阶段的当前产物登记；
* 清理对应内存状态、旧错误和旧 unavailable 记录；
* 旧文件可以保留，但不得继续被当前 `result.outputs` 引用；
* 阶段记录应表示当前执行，而不是不断追加无法区分的新旧记录。

暂时无法可靠支持局部重跑时，也至少应明确要求创建新 workflow，并阻止旧会话结果被当成新结果发布，而不是默默混用。

**注意：这不等于说当前全新 batch 运行一定有同样问题。**batch 已使用新 staging 和新 workflow；这里最直接影响的是交互式 Notebook 重跑。

## 3. Raw baseline 的抽样顺序仍然没有改对

这个问题上一轮就提过，最新代码仍然存在。

`stage_baseline()` 目前还是：

```python
sampled = deterministic_subset(whole_side, sample_n_units, seed)

for scope in scopes:
    cohort = self._scope(side, scope, adata=sampled)
```

即：

> **先抽全组织，再从抽样结果中取 Fibroblast。**

### 对 P2 的实际含义

当前配置是：

```text
Raw 全组织：340,837
Raw Fibroblast：26,152
sample_n_units：30,000
```

按这段逻辑，确认 Raw 表达后，不会因为 Fibroblast 少于 30,000 就保留全部 26,152 个 Fibroblast。

它会先从整个 Raw 抽 30,000 个单位。简单随机抽样下，保留下来的 Fibroblast **期望只有约 2,302 个**；这不是我对真实 H5AD 实测的数量，而是根据当前配置和抽样算法计算的期望。

然后就可能变成：

```text
Raw baseline：约两千个 CAF
SVC State：17,455 个 CAF
```

这会进一步影响 Raw 窗口支持、共同有效窗口，以及后续 Gain。

### 正确处理

先选择 scope，再决定是否抽样：

```python
cohort = self._scope(side, scope)
cohort = deterministic_subset(cohort, sample_n_units, seed)
```

本轮 P2 Raw Fibroblast 小于 30,000，因此应保留完整 parent。

**这一问题不推翻当前已经计算的 P2 主标签 State。**主 State 使用完整 SVC 标签，已经与表达抽样解耦。它主要会在 Raw 表达条件满足后，影响 baseline、Gain、K-control 和 membership。正因为这条路径当前尚未真实运行，所以问题暂时没有体现在现有 P2 结果中。

# 三、空间证据已经接起来，但还没有完全回答“集中在哪里”

这里我想区分：

## 1. Region × Anatomy 当前主要是总体组成，不是 Anatomy 内的 State 比例

`integrated_region_anatomy_summary` 当前主要保存：

```text
某个 State 状态 × 某个 Anatomy 中的单位数
÷
整个 parent 的单位数
```

对应的是：

$$
P(\mathrm{State},\mathrm{Anatomy})
$$

代码和图中的分母名称写得比较清楚，这本身不是错误。

但当你问：

> **CAF 高多样性 State 是否更集中在 Interface？**

还需要另一个量：

$$
P(\mathrm{State}\mid\mathrm{Interface})
=
\frac{\text{Interface 内 State 单位数}}
{\text{Interface 内区域状态可判断的单位数}}
$$

否则 Interface 本来单位就多，也会在总体组成图里显得“State 很多”。

### 建议补充的不是新算法，而是两个清楚的分母

同一张表里并列：

| 指标                             | 回答什么               |
| ------------------------------ | ------------------ |
| State × Anatomy 占整个 parent 的比例 | 这些单位在总体中占多少        |
| 各 Anatomy 内 State 的比例          | 这个组织背景内，State 有多常见 |
| 各 Anatomy 内状态未知的比例             | 这个比较受支持不足影响多大      |

仍然从现有单位底表汇总即可。**未知继续单列，不并入 State 外。**

这一步能明显增强最终综合阅读，而不增加复杂架构。

# 四、有两个小但明确的语义问题，应一起修正

## 1. Gain 摘要里的 `n_units` 仍然是人为取两侧最小值

`common_valid_delta()` 当前保留了：

```text
raw_n_units
svc_n_units
```

这是对的。

但随后又生成：

```python
n_units = min(raw_n_units, svc_n_units)
```

这个值进入通用 Region extent 汇总，被用于 `n_valid_units`、`n_region_units` 和 `region_unit_fraction`。

由于 Raw/SVC 不是一一对应，这个最小值**既不是实际 Raw 单位数，也不是实际 SVC 单位数，更不是配对单位数**。

例如两个窗口：

```text
Raw：4、100
SVC：100、4
```

最小值都是 4。用它计算某个窗口的“区域单位比例”得到 50%，但实际 Raw 和 SVC 的比例分别是约 3.8% 和 96.2%。

### 最小修改

Gain 可以统一报告共同有效窗口数和窗口面积；单位数则分别报告 Raw 与 SVC，或者干脆不提供一个含义不明确的统一单位比例。

**不需要为此增加 pairing，也不需要新建比较对象。**

## 2. 旧式共享表达声明与逐侧声明的冲突还没有检测

计划明确要求：

> 兼容旧声明，但不允许相互矛盾的声明混用。

当前 `Sample.expression()` 直接让逐侧声明覆盖共享声明，`read_sample_config()` 没有检查两者冲突。

因此类似：

```yaml
expression:
  scale: untransformed_nonnegative
  raw:
    identity: measured
    scale: log1p
```

仍会静默采用逐侧值。

这不影响当前 P2 的纯逐侧 unknown 配置，但应补一个简单的冲突检查，或明确禁止“共享 scale + 逐侧 scale”同时声明。**这只是防止配置歧义，不是重新引入复杂 preflight。**

# 六、关于“高多样性 State”的科学解释，还应保留两点提醒

这两点不是要求新增分析，而是帮助你正确审阅现有结果。

## 1. 当前 Neff 是固定抽样深度下的局部多样性

代码每个有效窗口抽取 `min_units` 个单位，当前为 4，再进行 200 次抽样取平均。因此这里的 Neff 是**四个单位抽样深度下的有效标签多样性**，不是窗口中所有单位的完整 Neff；它的上限也受这个抽样深度约束。

这不是错误，等量抽样正是为控制支持数影响。

但 Notebook 和网页在介绍指标时，最好直接写清楚，否则“10 个重建标签”和“Neff 约 2.4”容易被放在错误的尺度上理解。

## 2. State 内标签组成是解释，不是独立验证

State 本来就是从这些重建标签的多样性定义的。再发现 State 内多种标签共存，主要帮助解释区域由什么组成，不能当成额外的独立验证。

最新网页已经把这个边界写进阅读说明，值得保留。

下一步可以在已有候选尺度中检查例如 32、40、56 μm 的空间表现，但不要根据“哪一个产生最多 State”来选择尺度。重点是判断空间结构是否稳定、支持是否足够，以及这个定义是否服务于你真正关心的问题。

# 七、接下来应怎样推进

我建议分成三个层次，而不是再增加一轮大架构计划。

## 第一层：先修正会妨碍继续开发的实际问题

| 优先事项            | 修改重点                                 | 直接验收标准                                |
| --------------- | ------------------------------------ | ------------------------------------- |
| 阶段重跑一致性         | 清除/撤销该阶段及下游的旧 state、产物登记和状态          | 稳定→不稳定→稳定后，当前报告不混入任何旧结论               |
| Raw baseline 抽样 | 先选 scope，再抽样                         | CAF 数量低于上限时完整保留；增加其他组织细胞不改变 CAF 的抽样范围 |
| Notebook 即时图形反馈 | 支持、连续场、阈值和 Anatomy 图在对应章节生成与展示       | 不执行最后一个总绘图单元，也能完成前面阶段的视觉判断            |
| 项目参数一致性         | Notebook 与 batch 共用项目、样本、override 解析 | 项目明确覆盖参数时，两种入口仍一致                     |
| 两个语义小修          | 表达声明冲突；Gain 单位分母                     | 不静默覆盖矛盾声明，不把两侧最小单位数当实际单位数             |

这些都属于已经暴露的真实问题，不是为未来假想需求预建系统。

## 第二层：把当前 CAF 主线的阅读闭环补完整

这一层只补现有结果的连接和可观察性：

```text
支持曲线与显式尺度
        ↓
CAF Neff 连续场与阈值
        ↓
State mask
        ↓
共同坐标下的 Anatomy 对应
        ↓
各 Anatomy 内的 State 比例及未知支持
        ↓
State 内外的重建标签组成
        ↓
当前能解释什么、还不能解释什么
```

最值得新增的是：

**一张共同坐标关系图，加一张按 Anatomy 条件化的汇总表。**

它们比继续添加更多自动摘要文字更能帮助你判断区域定义是否合理。

## 第三层：推进真实表达分析，而不是提前扩展新生物学任务

当上游表达身份得到确认后，按前提逐步运行：

```text
确认 Raw 表达
    ↓
Raw Leiden baseline
    ↓

```

以及：

```text

    ↓

    ↓
共同基因对照、程序的条件化跨侧阅读
```

正式完整 `SVC.h5ad` 到达后，仍走现有单对象接口。不要新增旧双载体模式，也不要读取 `expr.h5ad` 临时拼表达。

**T、Mono/Macro 的真实验证和跨平台扩展，应作为下一阶段范围；不是当前 CAF 首轮验收的阻塞项。**CCI、TLS、单亚型 enrichment、自动 Agent 编排同样不应现在被塞进来。

# 八、验收方式还可以更适合交接和外部审核

现在已经有比较详细的验收文档，但其直接证据都在本地 `output/`。所以换一个 Codex 会话、换一台机器或仅从 GitHub 审核时，仍然主要依赖文字记录。

不必改变 H5AD 和大结果的 gitignore 规则。建议单独交付很小的一份验收包，包含：

* 本次 commit、配置和执行环境摘要；
* P2 标签空间链的关键计数与 Notebook/batch 比较结果；
* 几张代表性截图；
* 明确的“已执行／缺前提／尚未人工确认”列表。

这可以作为附件或独立发布产物，不一定进入代码仓库。**目的只是让“文档说做过了”能连接到可检查的证据，不是建立新的 provenance 平台。**

对于测试，下一轮最值得补的也不是更多“从头跑一次成功”，而是以下真实使用行为：

| 测试                     | 为什么现在需要                  |
| ---------------------- | ------------------------ |
| 同一 workflow 稳定阈值→不稳定阈值 | 防止旧 extent 和旧图残留         |
| 同一 workflow 不可用→前提恢复   | 防止旧 unavailable 状态继续污染结果 |
| 修改上游尺度后重跑下游            | 防止旧窗口、旧 Anatomy 关系混入     |
| 项目覆盖值与 Notebook 一致     | 验证真正的配置共享                |
| 全组织添加非 CAF 单位          | 确认 CAF baseline 不受全局抽样稀释 |
| Gain 两侧单位数强烈不同时        | 确认分母不被合并成伪配对单位数          |

当前已有的测试覆盖了标签不被别名改写、Anatomy 尺度不改变 parent 多样性、阈值失败保留连续表、未知状态不补零等重要行为；这些应保留，再补上述交互式和实际配置场景。

# 最终判断

我会把当前状态这样定义：

> **独立分析仓库的核心方向已经走对，P2 CAF 重建标签空间链已经达到可进入科学审阅的阶段；但 Notebook 的即时可视化与反复调参闭环、项目配置一致性、Raw baseline 抽样及部分比较分母，还没有完全达到要求。**

这次最重要的变化是：**现在不需要再重新解释“State 应该分析什么”了，主要精力应该转向“怎样可靠地检查、修改和解释已经计算出来的 State”。**

下一轮最有价值的顺序是：

**先修阶段重跑和抽样 → 把关键图放回 Notebook 对应位置 → 统一项目参数 → 补共同坐标关系图与条件分母 → 再推进真实 Raw/完整 SVC 表达分析。**

完成这些之后，你得到的才不仅是一套能跑完并生成网页的流程，而是一个真正支持你**沿连续科学主线看结果、判断实现、修改参数，并把判断后的同一套分析交给 batch 扩展**的开发工作台。
